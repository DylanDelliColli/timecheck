## Outcomes

Each outcome names its consumer surfaces; readiness predicts per surface. There is no
frontend in this release: the surfaces are data files, the build and its report, the
SQLite views, the CLI's JSON output, and the documentation an agent reads to use them.
Exact file layouts, schemas, view columns and commands are fixed in the design record
(`docs/releases/v1-design.md`).

- **O1 Sourced graph.** Entity files (brands and authorities, model lines, references,
  calibers, sources) under JSON Schema, where every relationship and attribute is a
  claim with evidence: source, pinned archived snapshot and hash, exact quote and
  locator, retrieval date, trust tier, match mode and status. Caliber relations
  (derived_from, clone_of, grade_of) and grades as entities; `uses_caliber` with
  production years; sourced `succeeds` edges for lineage. A build that validates
  schemas and references, verifies every snapshot and quote, refuses a claim without
  evidence, computes disputes from competing verified claims, compiles
  `timecheck.sqlite`, and writes a data-quality report. *Surfaces:* the data files and
  schemas; `timecheck build` and its report; the SQLite tables.
- **O2 From a watch.** For a reference or caliber: calibers by year with grade or
  `unknown`, the caliber family, and every reference across brands on the same caliber
  or family. *Surfaces:* the views `v_reference_calibers`, `v_caliber_references`,
  `v_caliber_family`, `v_shared_dna` and the CLI (`timecheck query … --json`).
- **O3 Lineage.** For a model line: references in order with calibers and years, and
  the attribute diff across each verified succession, disputed values side by side,
  unknowns as unknown. The Submariner is canonical; the A-11 shows three makers under
  one designation. *Surfaces:* `v_lineage`, `v_lineage_diff` and the CLI.
- **O4 Provenance.** Every row of every view is joinable to its evidence; a
  primary-only filter works on every query; the data-quality report states claims by
  status and tier, disputes, pending manual attestations, coverage per seed family and
  evidence share per source domain. *Surfaces:* `v_evidence`, the `--primary-only`
  and `--include-proposed` CLI options, the report.
- **Seed** (part of O1's acceptance): Rolex Submariner; Seiko Presage plus the other
  Seiko lines using its 4R/6R/6L calibers; Omega Seamaster 1960s–70s; ETA 2824-2,
  2892-A2, 7750 with Sellita SW200/SW300/SW500 and cross-brand host references; A-11
  from Elgin, Waltham and Bulova. Depth rule: the canary times ten references across
  the five families (including one scan-based primary source) and the measured cost
  sets each family's depth before the wave is dispatched. The v1 Submariner floor is
  the canary's references plus every reference with a primary source; the full
  reference table is the coverage target the report measures against. 150–300
  references and 40–70 calibers are targets, not commitments.
- **Docs for agents** (part of O2–O4's acceptance): a document that tells a programmer
  or agent how to build, where the views are, what each column means, and how evidence
  is attached, sufficient for the uncoached walkthrough.

Behaviour to preserve: none; this is the first release of a fresh repository.

## Size and team

Envelope: about one week of build. The canary unit (schemas, claim model, build with
evidence verification and all views, fixture tests, ten timed references) is built
first and validates the design; its measured sourcing cost is a hard gate on the wave.
Chief team: one chief, up to three concurrent workers, each in its own worktree with
its own build and SQLite file, so nothing is shared. Worker defaults from the roster
(codex / gpt-6.1-sol / high); the chief may choose another kind/model/effort per unit.
Independent reviews (fresh-context helpers, outside models where available) precede
every merge; the operator asked that decisions keep getting reviewed by independent
models.

## Taste and explicit constraints

Requirements:
- No claim from agent memory. A worker that cannot cite a claim leaves it out and notes
  the gap on its bead.
- Evidence is machine-checkable: pinned archived snapshot, hash, exact quote; the build
  verifies it. Fuzzy matching only for PDF text layers, with digits and years exact;
  image scans need human attestation and stay `proposed` until the operator attests.
- Unknowns are shown as unknown; disputes as disputes; `none` is not `unknown`.
- Grade is part of caliber identity in every output.
- A reference that used several calibers shows all of them with their years.
- No full-page text of a cited source in the repository; no systematic extraction from
  cite-only sources; per-domain cap enforced in CI; non-commercial sources banned.
- Local-first: a clean checkout builds and tests with one command each, without network
  (fixture snapshots on disk); network is needed only to verify live archives.
- Licence: ODbL 1.0 + DbCL on `data/`, MIT on code, DCO sign-off on every PR.

Guidance:
- Plain relational tables and views; recursive CTEs for families; no graph database.
- Schemas and docs written for an agent reader: explicit vocabularies, explicit
  column meanings, examples.
- Keep the schema open to a later price-observation table, a parts slot and external
  identifiers; build none of them.

Host limitations: WSL2 host shared with other agents; Python 3.13, Node 22, Rust 1.96
and bun available, no Go. Workers run builds and tests in their own worktrees and do
not stack heavy runs.

## Real inputs and journeys

Input families (public web; no restricted data; no held-out set):

1. Wikipedia reference tables and prose (open): Submariner reference table at a pinned
   revision, Seamaster, Presage, A-11.
2. Manufacturer pages and documents (primary): Rolex current-model pages; Seiko
   product and caliber pages; Omega vintage database; ETA, Sellita, Miyota, Seiko
   technical sheets; USAAF/AN specification documents (public domain where
   government-authored); dated catalogues and advertisements, often scans.
3. Enthusiast references (secondary, cite-only): Ranfft DB, Caliber Corner, EmmyWatch,
   17jewels, Watch Movements Archive, Pocket Watch Database and maker serial databases,
   forum and dealer guides.
4. Wikidata (open) where it has anything.

Who supplies what: workers fetch public sources, pin archived snapshots and record
quotes themselves; the operator supplies no private data. The operator's real input for
the pre-readiness check is the question "what is in a 1970s Omega Seamaster and what
else shares it", answered through the CLI against the built database.

Held-out set: none. In its place, evaluation runs a **provenance audit**: a random
sample of verified claims is checked against their pinned snapshots for faithful
transcription, and the aggregate (sample size, faithful, unfaithful, snapshot
unreachable) is reported.

Real-journey checks:

1. Before first readiness: the full seed builds from a clean checkout with evidence
   verification against live archives, time measured; deliberately bad fixtures (no
   evidence, quote absent, hash mismatch, unresolved slug) are shown to be rejected.
2. Before first readiness: the operator's Seamaster question and the Submariner lineage
   are answered through the CLI and SQL, in the chief's lane.
3. Before acceptance: an uncoached walkthrough by a code-blind evaluator from an empty
   checkout, using only the documentation, the build and the CLI, answering PRD use
   cases 1–5.

## Scope boundaries

In scope: O1–O4, the seed under its depth rule, the agent docs, the GitHub repository
with CI (validate, strict build, tests on every PR; nightly full evidence
re-verification), the data-quality report, and a baseline note that the base commit
contains no product code.

Excluded: any frontend or static site (a wireframe is parked outside the repository);
JSON/CSV exports; an MCP server; external identifiers for other databases; prices;
parts; agentic supplier-catalogue parsing; hosting; accounts; outside contributions
before the operator opens them; bulk extraction from cite-only sources; brands and
lines outside the seed (the schema must take them; the seed does not include them).

Default allowance kept: small fixes in code already being changed, covered by tests and
declared at readiness. Standing default kept: fixes for silent data loss in touched
paths are in scope. Other findings outside the release are filed as beads and flagged
to the operator.

delegation in comment 4 on `timecheck-wfn`):

## Interrupt policy

An urgent fix reaches `main` only through the operator, who merges it; the chief then
merges `main` into `release/v1`. None is expected in a fresh repository.

## Release authority

- The chief alone merges pull requests into `release/v1`, each on the exact head whose
  required checks passed, after an independent review.
- The operator merges `release/v1` into `main` after evaluation; evaluator acceptance
  grants nothing.
- No deployment. The remote is the operator's private GitHub repository `timecheck`;
  the chief pushes `main` and `release/v1` and worker branches there. After the
  operator's merge, the chief creates the annotated tag `v0.1.0` at the merge commit
  and publishes a GitHub pre-release with the SQLite build attached; making the
  repository public is the operator's decision.
- Resource limits: at most three concurrent workers; no shared services; everything
  local except GitHub.

## Release close

As in the Alleyoop release template: whoever creates a worktree removes it after
checking for live processes and uncommitted, unmerged or evidence-like content;
review checkouts live under the session's temporary area; at close the chief lists
remaining worktrees and branches, removes merged ones, keeps the final round's
evidence plus anything a retained report references, and posts a close receipt on
`timecheck-wfn`.
